## Ordered A · non-circular trust before the first PID-derived `/proc` selection

1. **EXPECTED, independent of runtime claims.** Before selection/launch, register immutable expected *actual daemon-used init* object and bytes, source/build/native closure, full interpreter/loader/DSO and continuing-load policy, unchanged full imported container policy/pins/output target, and complete selected recipe. Independently fix the expectation before any daemon/worker report, selected pathname, digest or observed object can nominate it; an expected hash alone does not prove immutable backing or execution. G1/G4 and the sole host-Rust owner's own trusted loading remain separate OPEN gates.
2. **Trusted effective daemon selection of the SAME opened object.** Establish which init the daemon effectively selects and how a trusted, source-bound launcher retains identity from *that* opened object to its selected runtime input; do not substitute the path returned by Moby [`GetInitPath`/`LookupInitPath`](https://github.com/moby/moby/blob/v28.5.1/daemon/config/config_linux.go). Authenticate the selection and every copy/seal/handoff edge without letting the selector attest to its own EXPECTED. Unknown installed daemon route or untrusted selection: STOP.
3. **Mount source/object and continuing HOST backing.** Show that the [`withCommonOptions` source → `/sbin/docker-init` `bind,ro` mount](https://github.com/moby/moby/blob/v28.5.1/daemon/oci_linux.go), when the `--init`/private-PID branch applies, refers to that SAME selected opened object through setup and execution; qualify continuing immutable **host** backing, writable aliases and object identity. `bind,ro`, a mount path, file hash, opened FD or copied bytes alone proves neither source identity nor immutable backing. G2 and actual host kernel/filesystem qualification remain OPEN.
4. **Kernel executes that SAME object.** Bind the eventual init kernel-exec object to the opened/mounted expected object, including any script interpreter, ELF loader, DSO or later executable closure. The checked runc [`Init` → `exec.LookPath`](https://github.com/opencontainers/runc/blob/v1.3.2/libcontainer/standard_init_linux.go) → [`system.Exec`/`unix.Exec` pathname](https://github.com/opencontainers/runc/blob/v1.3.2/libcontainer/system/linux.go) route does **not** prove object identity across lookup/exec. A *hypothetical* FD-targeted `execveat`/`fexecve` route or separately qualified immutable backing is only a candidate, never proof of the actual selected route; changing it needs explicit review. The [runc intermediate `runc init` memfd](https://github.com/opencontainers/runc/blob/v1.3.2/libcontainer/container_linux.go) is not the daemon-used `docker-init` object.
5. **Host-Rust pre-read handoff.** Deliver independently authenticated, session-bound, non-replayable, role-bound provenance for the **same actual executed init object** from the qualified creator/launch chain to trusted host Rust **before** its first PID-derived `/proc` pathname or reliance on a purported child handle as authority. Bind sender, selected container, generation, receiver, lifetime and continuing revocation to the same session; FD possession, sender report, PID/pidfile, mount path, digest or runc memfd alone does not supply this chain. The separately owed Tini fork→**after-exec actual main Node** handle, independent after-exec reference Node handle and each independent attach→actual Node FD0/1/2 route remain OPEN under the [dual-provider contract](native-ingress-r-out-dual-provider-contract.md); init provenance cannot substitute for either provider.

**B · later, independent gate:** Only after A, separately decide/approve and prepay a race-safe check of the **actual same opened daemon-used init** bytes, live root and PID namespace, before **any** authority. Separately qualify handle→exact-path safety, permitted access and continuing validation; B cannot backfill missing A or make an earlier PID-derived proc read safe. A never asserts full B was already performed.
