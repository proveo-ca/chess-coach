## 2. Candidate topology and independently fixed expectations

One captured, immutable-loading **host Rust owner** would hold the sole direct meter, original clocks, F1 and private live gate. ONE owned, read-only, policy-constrained container would run the **fixed worker Node as its main application** under Docker's init. The fixed **independent Node reference** would be a **separately approved mutating ExecID** in that SAME container, with its own independently bound attachment. `exec` starts another command; it does not give custody of the main process. No second container, daemon socket, new user mount, dynamic endpoint or privilege change is authorized. Init is PID 1 in the container PID namespace; the main Node is its child, **not** PID 1, and an ExecID/CLI child is neither Node's process handle nor proof of Node's death or reap.

Before worker claims or runtime outputs, independently register expected **source and mixed Rust+Node/native graph**, fixed worker and genuinely independent reference, captured compiler/tools and native/loader closure, exact build/runtime/archive/image recipe and immutable RecipeRef, complete policy and imported pins/output binding, expected static-ELF properties and Rust owner artifact, Node runtime/executable/bootstrap and separately approved daemon init **bytes**. Register the source/recipe/policy selection before building; later independently measured image/rootfs identities join that selection before launch and cannot redefine it. Static ELF means actual `PT_INTERP`/`DT_NEEDED` absence plus audited late-load closure, not an asserted build flag. A hash, image ID, pathname, reported version or observed stream cannot elect its own expected value. The trusted staging/immutable-host-owner loading and first owed-work classification of [ownership G1–G5](native-ingress-ownership.md#135-bootstrap-gates--one-owner-before-owed-public-work) remain OPEN; actual local seal/ELF/kernel qualification is not inferred.
