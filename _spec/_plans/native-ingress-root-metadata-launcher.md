## Selected-A unresolved envelope

- The outer launcher alone opens/reads **one** bounded document snapshot; parent and entry perform **zero** document reads. Its read/close and identity checks, snapshot mutation and stable-path/ancestry trust are unresolved. The fixed Node executable identity, library/config/preload loading and trusted **pre-start** environment (including inherited descriptors and options) remain **OPEN**; `env: {}` applies only to the child and does not settle parent startup. Canonical base64 arguments expose control bytes to local process observers and consume OS argv capacity; they are neither secret nor guaranteed to fit without a reviewed size limit and error path.
- Fix the exact outer owner, child and process-group topology; define EOF, exit, termination and **reap** requirements for every owned process and stream. Start the external **5000-ms wall clock before any startup**, not at the parent's later 4500-ms timer. A SIGKILL request is neither proof of termination nor reap. These mechanisms and their failure effects remain **OPEN**.
- Parent cannot verify its own pre-execution identity. Controller's six `lstat` calls bound only its installed-root metadata observation; the **single launcher snapshot**, Node startup, argument exposure/limits, outer capture and teardown require their own reviewed effects envelope. A successful metadata record proves neither immutable root custody nor Native authority.

## Offline synthetic test contract — six-case static/model subset recorded

**Intended verdict: STATIC/SYNTHETIC ONLY, never operational PASS.** The selected-A test contract calls for synthetic document bytes and **independent, preselected** expected lengths and digests for each of the three fences. A complete harness would count exactly one bounded outer snapshot read and close, locate exactly one complete controller, entry and parent fence each, and compare the extracted byte sequences (including final LF) to those pins **before** any fake Node start. The expected values must come from a separate fixed test input, never from the snapshot under test. A future launcher must forward the very bytes it checked: `--eval <checked parent> -- <checked entry64> <checked controller64>`; the parent must forward the same checked entry and controller through its child invocation. Fake document access after the one snapshot is a failing assertion, including in parent, entry, child and failure cleanup. No reread to repair a changed document is allowed. The current six-case suite is only a subset of this future complete harness.

The future complete harness would need to exercise each executable boundary without exposing host-realm capabilities: the earlier VM approach admitted a HIGH-reviewed `Buffer`/`crypto` escape risk and is **not** the current verification method. Require independently checkable digest results against fixed fixture pins, an isolated fake filesystem for the six literal `lstat` calls, and fake child streams/process events that cannot create a host process. Never execute the actual fenced controller with host `require`, real `spawn`, or installed paths; never let a synthetic success claim real Node loading, immutable ancestry, physical process-tree termination or Native authority. These are design requirements, **not a claim that every matrix row was tested**.
