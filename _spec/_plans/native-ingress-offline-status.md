# F9 offline `mise` status · static refusal only

With its helper present and no arguments, `mise run f9:status` prints a fixed prerequisite reminder and returns `RESULT=STOP`/exit 2. Missing or symlinked helper and extra arguments also refuse with exit 2; the missing-helper branch prints only `RESULT=STOP`. The wrapper checks the helper's file type; neither wrapper nor helper inspects actual approval records, F9 source content, tests, host readiness, VM state, `sbx`, Cargo, or evidence. Its labels describe obligations; they do not assert current gate values. No change in the checkout or environment can turn this task into F9 authority. A passing command would require a separately designed, independently accepted verifier and actual evidence, not a changed literal or success stub.

The [ML navigation](PLAN-ml-adjutant.md#immediate-ordered-next-actions--train-the-first-broader-adjutant) keeps R4/R5 readiness separate from F9 and R6 permission.

`mise` may load checkout or user configuration before task code starts. This command is a convenience display, not a secure host entrypoint or a side-effect-free claim about `mise` startup.
