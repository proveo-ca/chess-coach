## Conceptual kernel-internal states — no interface selected

| Transition | Required proof, bound and refusal |
|---|---|
| `ABSENT → PENDING` | Admit capacity **before** retaining any object or session state. An independently qualified pre-attempt kernel-side custodian retains a kernel-owned reference to the **original kernel-opened actual main Rust executable object**, bound to the specific attempt, task incarnation and independently anchored `EXPECTED` join, after original S0 precedes all launch-causal work. This is not merely a pointer value, FD number, pathname, inode, digest, reopen, equal bytes or launcher callback. Preserve reference/lifetime through selection, binfmt iteration and failures; classify even admission, reference acquisition and S0 capture for owed pre-owner effects **before** performing them. |
| `PENDING → COMMITTED` | Only definitive successful exec **of the SAME retained original main object**, after remaining fallible steps, with the correct **new Rust exec generation** and task incarnation, can commit. A pre-exec event, `point_of_no_return`, `self_exec_id` increment, old launcher's return/EOF, PID or filename cannot commit. Failure including post-point-of-no-return (PNR) death instead enters the `PENDING → FAILED → QUIESCED → DISPOSED` refusal path, even if the old launcher cannot report it. No failed or ambiguous attempt is retried, rearmed as a new attempt or allowed a new meter. |
| `COMMITTED → READY` | Produce only an independently authenticated, exclusive, one-use, finite-transit receipt for the **correct newly executed Rust generation**. Bind issuer, session, boot, role, original object/attempt, task incarnation, exec generation, original S0 and explicit clock ID/suspend/namespace/offset or bounded authenticated translation. Prove before-event complete coverage, ordered gap/loss/overflow refusal, integrity, replay rejection and delivery **before reliance**; a success event alone is not a delivered receipt. |
| `READY → ACTIVE` or `READY → REVOKING` | Independently qualify the sole correct Rust recipient and accept its READY receipt **once**, atomically/race-safely against revocation: only one transition wins. Acceptance consumes the receipt to prevent replay, **not** the retained original opened object or the independent immutable-closure custody. A losing acceptance fails closed, including races with reexec, exit, recipient death or policy/credential invalidation; wrong recipient, stale generation, replay, late or lost delivery cannot activate. No second receipt, meter, attempt, retry or rearm. |
| `ACTIVE → ACTIVE` | Each permitted reliance/loan must remain bound to the same original opened object, authenticated generation, full independently EXPECTED-joined immutable loaded/continuing closure and qualified custody **for its entire duration**, not only at acceptance. Track in-flight reliance/loans under a bounded, race-safe admission and quiescence protocol; receipt consumption never releases these references. No new reliance may begin once close or revocation wins admission. |
| `ACTIVE → QUIESCING → QUIESCED → DISPOSED` | Normal close first blocks new reliance; quiesce **every** in-flight reliance/loan, then dispose retained original opened object, immutable-closure custody, receipt/carrier and session artifacts under a surviving qualified owner. Neither receipt consumption nor close request alone permits release; successful quiescence is the prerequisite for disposal. |
| `ACTIVE → REVOKING → QUIESCED → DISPOSED` | Reexec/competing exec, task exit, recipient death, cancellation or credential/policy/namespace invalidation **immediately blocks new reliance** through race-safe admission; quiesce every already admitted reliance/loan before disposal under surviving qualified ownership. Revocation does not retroactively make in-flight custody safe to free; refuse any unprovable in-flight ordering, identity or closure validity rather than silently releasing it. Forced removal is not a clean close/EOF/reap. |
| `READY → REVOKING → QUIESCED → DISPOSED`; pre-READY refusal | Revocation wins against READY acceptance or loses to ACTIVE and then revokes it; no ambiguous acceptance is permitted. `COMMITTED → REVOKING → QUIESCED → DISPOSED` applies before readiness; `PENDING → FAILED → QUIESCED → DISPOSED` applies on failure, including post-PNR death, and `PENDING → REVOKING → QUIESCED → DISPOSED` on invalidation. Each path needs surviving-owner cleanup and quiescence of any admitted loan before disposal. `FAILED` and `REVOKED` are terminal **refusal** outcomes, never READY or a second opportunity; they do not authorize disposal of a still-active loan. |
| All cleanup paths | Independently qualified surviving kernel/issuer ownership bounds quiescence, retained references, age and terminal cleanup within the **original S0+300s**, reserving its **final 3s for cleanup**, even if old launcher or new Rust dies. Invoice and prepay any owed cleanup liability **before it is incurred**; if it is owed before the first successful DIRECT debit and cannot be prepaid, **STOP before incurring it**, including before retention when retention creates that liability. Refuse admission unless worst-case loan drain and disposal fit the bound; never omit cleanup, silently abandon a loan, restart S0, refund or count disposal as clean close. |

**Race/identity refusal:** A fork or competing exec must not borrow the original attempt's custody or receipt. Task-incarnation reuse, PID reuse, exec-generation wrap, reexec and credential/namespace transition must not resurrect an old READY or ACTIVE state. Prove atomic/race-safe acceptance versus cancellation, success/failure and exit, and race-safe admission versus quiescence, with the same-object/final-closure check and retained immutable-closure custody valid throughout **ACTIVE and every continuing in-flight reliance during QUIESCING or REVOKING**; refuse if ordering, task identity, generation, reference lifetime, immutable aliases or recipient exclusivity cannot be proved. Bind the **actual** ELF `PT_INTERP`, loader, every DSO, environment-selected and continuing executable load, and every writable alias against independent EXPECTED: main-object custody alone never proves final loaded closure or immutable backing. Binfmt may rewrite `bprm->file` to an interpreter; `bprm->executable` retains the former file only conditionally. ELF's separate `PT_INTERP` open is **not** that binfmt rewrite. Neither field alone universally identifies the original main object. No choice of hook or kernel API follows from this description.

**Finite resource admission:** Specify maximum simultaneous sessions, retained references, in-flight loans, quiescence time, bytes and age, plus peak CPU/RSS/PIDs/FD/storage/output/time for issuer, launcher, kernel custodian, transport and cleanup with feasible overlap. Refuse **before object retention** when capacity, original-S0 deadline, worst-case loan drain, prepaid cleanup headroom or independent proof is insufficient. No silent eviction, unbounded queue, unlimited holding period or host-wide unbounded wait. Cleanup must remain independently qualified after old launcher replacement or new Rust death. No claimed bound or effective enforcement has been established by this document.
